# 应用清单 1.0

原生 WPF 桌面程序，面向 Windows 10/11。显示本机当前用户可读取的桌面和商店/MSIX 应用记录。

## 启动

收到发行 ZIP 后，先解压整个目录，再运行其中的 `AppInventory.exe`。首次启动只读取安装记录；点击“扫描范围…”后才开始目录扫描，默认覆盖所有已就绪的固定磁盘，可添加目录或排除整个盘及指定目录。扫描过程中可以搜索既有清单或停止扫描。

开发目录可直接运行 `../artifacts/inventory/AppInventory.exe`，或在上一级目录执行：

```powershell
.\Start-Inventory.ps1
```

版本 1.0.0，面向 Windows 10/11 x64。`artifacts/inventory` 是依赖 .NET 8 Desktop Runtime 的开发构建。通过上一级的 `Build-Release.ps1` 生成 Windows x64 自包含 ZIP，接收者无需额外安装 .NET 8。单独复制 EXE 无法运行。当前提供便携发行目录，不注册系统安装记录。

1.0 的正式范围为软件清单、只读目录检查及报告导出。卸载测试属于独立实验入口，仅接受本工具创建的专用测试应用，普通软件没有卸载或清理入口。

## 使用

- 在搜索框输入应用名称、版本、发布者或路径。多个关键词按“全部满足”筛选，不区分大小写。
- 点击名称、版本、关联位置、路径或空间列标题切换升降序。空间按字节数、关联按数量排序，未知值始终放在末尾；数字版本和自定义版本分组排序。
- 可按桌面、商店和便携候选筛选，或只看有关联位置、用途待核实的记录。搜索也匹配主程序和关联候选路径。
- 选中一行，在右侧查看完整路径、路径来源、系统报告大小和测量值。
- 点击“扫描范围…”配置固定磁盘、额外目录及排除项，再开始便携软件和关联目录检查。默认检测所有已就绪的固定磁盘，也可关闭该选项，仅检查手动添加的目录。
- 扫描时按钮变成“停止扫描”。取消后保留上一轮完整结果；完成后才将便携候选合并到清单。扫描范围和最近一次完整清单自动保存到本地，重启后无需重新扫描即可查看历史结果。
- 顶部“目录快照”显示实际扫描时间，提示这些是可能过时的历史结果。刷新只更新安装记录，不更新目录扫描时间；版本或安装路径改变的记录不会套用旧版测量和关联。历史便携候选可能已移动或删除，需要重新扫描核实。
- “关联位置”列显示候选数；详情区列出候选路径、大小和判断依据。下载、同步、缓存、旧副本目录都可能包含需要保留的数据，不是清理建议。
- 每条记录显示一段软件说明和来源。优先使用有效的本机说明；已核实的常见软件使用内置官方介绍摘要。没有可靠用途说明的记录展示已知事实，并标为用途待核实。
- 点击“测量目录大小”只读取选中目录下的文件元数据，不读取文件内容。再次点击可停止；取消或失败会保留原值。
- “复制路径”将当前路径放入剪贴板；“导出结果…”将当前筛选、排序后的记录保存为 CSV 或 JSON。CSV 使用带 BOM 的 UTF-8，包含目录大小依据及关联明细，并对可能被电子表格执行的自报公式加以转义。JSON 保留结构化关联、时间和实际扫描范围。导出文件含软件信息和本地路径，请在分享前自行检查。
- `Ctrl+F` 聚焦搜索，`Esc` 清空搜索，`F5` 重新读取安装记录。

常规软件清单没有卸载、清理、删除扫描结果、启动扫描到的软件、注册表编辑或自动更新功能。表格和路径字段均只读。单击说明的 HTTPS 来源链接会打开默认浏览器；应用不会自动联网查询或上传软件名称、本地路径和扫描结果。独立的“卸载测试…”窗口只操作本工具创建的专用应用，不能将清单中的软件传入该入口。

## 专用卸载测试

1. 点击“卸载测试…”打开独立窗口，创建测试应用，核对会话、路径、命令与辅助程序 SHA256。
2. 选择正常卸载、模拟失败、未实际卸载或耗时场景，再执行测试。先运行刚复制的测试应用确认其可启动，再通过 BCU 调用本程序的专用辅助入口。
3. 只有退出码和文件状态都确认成功后，才开放测试残留预览。隔离将已知缓存移动到本会话的隔离区，恢复不会覆盖已存在的目录，也不会重新安装程序。
4. 测试程序本体移动到本会话备份位置，保留的数据哨兵不移动，不执行永久删除。会话日志及 JSON 报告说明实际结果，历史会话可重新载入并恢复已隔离的缓存。

多个实例先后操作同一测试会话时，每次操作和导出都会在取得会话锁后读取最新日志及执行结论，避免旧窗口覆盖新事件或导出过时记录。操作进行中，其他实例的操作与导出会被阻止，可在测试结束后重试。

重新载入、操作和导出时也会核对历史成功结论的文件证据。程序已备份但缺少保存结果时显示“上次执行未确认”；历史成功记录与当前程序、备份或完成标记不符时显示“状态已改变”，均不授权残留隔离。原有事件及保存结果保留供核查，不自动补报成功、重装或回滚测试程序。

交互测试位于 `%LOCALAPPDATA%\AppInventory\uninstall-lab\<随机会话标识>`，自动检查使用输出目录的 `read-only-fixtures/uninstall-lab/`。会话标记、精确路径、文件内容、哈希与路径链接均会核对；测试组件摘要固定在主程序构建中，同时替换标记和程序也无法将任意软件当作测试应用运行。会话操作使用文件互斥，阻止其他实例重复执行。额外文件、篡改计划、目录联接、失败退出、退出码与实际状态不符时均阻止隔离。扫描清单默认排除本工具的交互测试目录。

随包测试应用由 Windows 自带的 .NET Framework 编译器构建，运行测试组件需要系统已有 .NET Framework 4.x；如果组件不能运行，测试会停止，不自动安装运行时或修改系统设置。主应用的 .NET 8 运行时仍由自包含包提供。本阶段不包含真实 MSI、NSIS、商店应用、注册表残留或系统重启兼容性验证，不应将专用测试结果视为真实软件卸载已就绪。

应用只写入自己的本地记录和用户明确选择的导出文件。本地记录位于 `%LOCALAPPDATA%\AppInventory\settings.json` 和 `snapshot.json`，包含扫描范围、软件信息和路径，按当前 Windows 用户的文件访问权限保存，不额外加密。保存采用临时文件替换，失败时提示并保留可用界面；格式损坏时跳过快照并重新读取安装记录。运行自动检查使用独立合成目录，不会读写上述正式设置。

JSON 记录与 JSON 导出上限为 32 MiB，写入前核对大小，超限时保留旧文件并提示。大清单可缩小筛选范围后导出 JSON，或改用 CSV；快照保存失败时本次清单仍可查看和导出，但下次启动可能恢复到上一次成功保存的快照。0.x 快照格式继续兼容，无需迁移或删除原数据。

## 常见情况

- 没找到便携软件：安装记录不会覆盖所有程序。检查是否已扫描所在磁盘、该目录是否被排除，以及候选程序是否属于安装缓存或辅助组件。
- 空间显示“未提供”或“≥”：前者表示系统没有报告数值；后者表示有跳过项，仅能得到下限。点击目录测量可以更新选中应用的逻辑大小，不能据此推断可释放空间。
- 没发现其他盘留存：名称和元数据关联可能漏掉自定义目录。可补充扫描范围，不能将“无候选”理解为不存在个人数据或残留。
- 启动后数量与上次不同：安装记录会重新读取，目录快照保留上次扫描时间。版本改变不沿用旧测量；便携候选和关联目录需要重新扫描核实。
- 本地记录有读写提示：查看目录快照的提示和状态栏。原文件会在保存失败时保留；可以先导出当前结果，不需要清理软件或修改注册表。

## 数据边界

桌面应用复用 BCU 的 `RegistryFactory`，只读取 HKLM/HKCU 的卸载记录，不调用完整应用发现、启动项、缓存或残留扫描流程。商店/MSIX 应用直接使用 Windows 包管理读取接口，不启动带卸载能力的辅助程序。

隐藏的系统组件、更新记录以及框架、资源包等默认不显示。安装记录仍只读取当前用户可访问的信息；磁盘扫描只读取当前权限可访问的选定范围，不提升权限。

便携识别核验 EXE 的 PE 文件头和版本资源，排除明显的安装器、卸载器、更新器和崩溃报告助手；同一个普通程序目录的辅助文件按主程序候选合并。工具容器中直接放置的独立 EXE 分别作为单文件候选，只统计该 EXE 的大小。未发现安装记录不等于已确认该程序完全便携，界面统一标为“便携 / 未注册候选”。

扫描只遍历一次，记录目录名称和大小索引，然后为各条软件记录匹配名称、可执行文件名、包标识及已知别名。除下载、缓存、备份等后缀外，也匹配 Tmp、Temp、临时和临时文件后缀，例如 BaiduNetdiskTmp，并将其标为“临时 / 缓存目录候选”。目录名称匹配只表示可能关联；版本文件的产品名匹配可作为程序副本的额外依据。用户自定义名称的缓存、存档或未知位置仍可能漏识别，不能保证找到全部留存。

路径中完整名称为 Package Cache 的目录及其子目录不新增便携候选，包括直接选择其中的子目录时；仍会读取目录大小并保留名称关联。这项规则不影响 Package Cache Tools 等相似名称，也不会泛化过滤所有 Cache 或 Temp 目录。目录名称仍是启发式依据，不构成归属或可删除证明。

默认跳过 Windows、回收站、恢复目录、Git 元数据、node_modules、虚拟环境和本工具的合成测试目录，并跳过链接与无法访问的项目。用户可以进一步排除任意目录及其子目录，也可以排除整个盘。未被系统识别为固定磁盘的位置可用“添加目录”显式加入。

没有安装路径时，若图标指向一个现有程序文件，详情区会明确标记“图标所在目录推断”。这不保证是完整安装目录；无法可靠读取时显示“未提供安装路径”。

默认空间是系统安装记录的报告值，可能缺失或过时；缺失时显示“未提供”，不会显示成 0。手动测量的是目录逻辑字节数，不是磁盘实际分配空间，也不是卸载后可释放的空间，不包含目录外缓存或用户数据。

测量不会跟随条目中的符号链接或目录联接；遇到无法读取的条目会标记为部分结果，并以“≥”显示下限。盘符根目录、Windows、Program Files 等公共根目录会被拒绝。现有权限无法访问的目录会显示提示，不申请管理员权限。

## 验证

在源码仓库根目录首次执行 `Initialize-Dependencies.ps1` 还原固定版本 BCU 后，再执行：

```powershell
.\Verify-Inventory.ps1
```

脚本会构建应用，运行合成数据的界面逻辑、目录测量、便携识别、跨盘关联及受控卸载检查，然后执行真实只读安装记录枚举。只读扫描检查在 `read-only-fixtures/` 和 `portable-fixtures/` 的随机子目录中创建数据，不运行扫描到的软件。受控卸载检查仅运行固定摘要的随包测试组件及专用辅助入口，在 `read-only-fixtures/uninstall-lab/` 内验证程序备份、缓存隔离和恢复，并创建测试目录联接验证拒绝行为；不永久删除数据，也不操作现有软件。自动验证不会扫描真实整盘；真实整盘验证通过界面显式启动。枚举日志只保存数量、字段覆盖率和读取提示，不导出完整软件清单；专用卸载报告仅包含相应会话信息。

发行包验证使用 `Verify-Release.ps1 -PackagePath <ZIP路径>`，同时要求对应的 `.zip.sha256` 文件；会核对摘要、二进制版本、运行时与声明，检查未混入本地快照和测试数据，再从解压副本运行自动检查与真实只读枚举，并输出只含计数与摘要的 `verification.json`。历史构建和验证问题保留在开发目录报告及日志中。
